Make record changes in org proposal cards render as live objects with the metadata a person decides on.

## The problem (Ashot, Oct 8, on op-57: 64 record changes)
Each task_status / plan_status / project_status row renders as a plain sentence: "Mark the plan <title> as done." then the reason. The reader cannot open the object, and cannot see what decides the call: its current status, when it was last touched, who owns it, how far along it is, and what proves the change (commit, comment). On a 64-row card that makes approving blind.

## Where
- Rows are built in packages/web/components/org/proposalTree.ts (case "task_status" | "plan_status" | "project_status", around line 256); sentences and nouns in proposalSubjects.ts (NOUN map, recordAct); groups in orgRecordGroups; fixtures in orgRecordsFixture.ts.
- Reuse what exists: EntityIdPill.tsx (the live ct-/pl- pill that renders title, state and a link) and DatePill.tsx. Do not build a parallel pill. The change contract is packages/shared/contracts/orgProposal.ts (OrgTaskStatusChange / OrgPlanStatusChange already carry plan and project, filled by the server at post time).

## Goal
1. Each record row leads with the record's live pill (ct-N / pl-N / project), so it opens the object in one click, followed by the move in plain words: current status to proposed status (e.g. "in progress, to done").
2. Beside it, the metadata that decides it, read live, not frozen at post time: last activity (relative date with the absolute date on hover, via DatePill), owner or assignee, and for a plan its progress (done/total tasks). For a task, its plan.
3. The reason stays as the row's second line. Commit shas and short ids inside a reason render as their existing pills/links (a sha links to the commit on the repo).
4. The group header already summarizes counts; add the date span of the group's last activity so stale-at-a-glance is visible.
5. Dense: one or two lines per row, aligned columns for status and dates, the same look on the org page card and the inline card in a thread. Follow the codebase's existing proposal card styling.
