### Source facts that materially shaped the design

**An anchor already separates identity from hosting.** The bot user provides a visible identity, while a human host runs the session. That makes it a useful durable role primitive. It does not make the bot's displayed name an authenticated service principal.

**Session ownership already has separate dimensions.** Human owners, runner/biller, device and initiator answer different questions. Adding a reporting role should preserve those meanings. Putting bots into the human owner set would break the existing inbox responsibility model.

**The task association is historical, not an exclusive lock.** `tasks.conversation_ids` records related sessions. The inspected `tasks.update` binding path can associate more than one session with a task; checking a conversation's current task does not reserve that task against another claimant. A managed attempt needs its own atomic claim contract.

**Nesting has existing semantics.** `parent_conversation_id` identifies contained subagents. `spawned_by_conversation_id` records provenance, with special presentation for Claude team members. The shared rider traversal handles chains, but the existing cleanup and individual surfaces need explicit review. Supporting a deeper placement model does not automatically build an organization UI on mobile.

**Account capacity and session consumption are different measurements.** Messages can carry token usage. Provider window percentages come from account reporting. Neither a percentage nor an absent receipt should be converted into an invented dollar cost. The declared `anchors.daily_session_cap` was not an enforced budget in the surveyed implementation.

**Current summaries have different purposes.** `cast summary` and `cast handoff` extract transcript structure deterministically; server insights and story summaries use model generation. Both can help recovery. Neither guarantees that a test ran, an artifact exists or a user accepted the result.

**Current messaging uses human authorization plus attribution.** `performSessionSend` validates the caller's right to send to the target; its optional sender reference supplies provenance. Managed agent authority requires an additional authenticated actor context. A source guard checking for a function name cannot establish that trust.

### Build decisions and alternatives

| Decision | Recommendation | Alternative and reason to defer |
|---|---|---|
| Durable role | Generalize `anchors` | A separate role entity duplicates standing identity and wake machinery; revisit only if the anchor contract cannot stay compatible |
| Management structure | Reporting tree derived from explicit work scope, with optional missing levels | A fully editable graph creates ambiguous authority and difficult moves before the basic loop is proven |
| Work management | Keep tasks, plans and projects canonical | A new agent-only backlog creates two versions of commitments |
| Specialist support | Bounded consultation with one accountable lead | Matrix management grants overlapping control and makes escalation unclear |
| Context | Small brief with source links and authorized retrieval | Full transcript inheritance increases cost, privacy exposure and stale assumptions |
| Execution | Existing harnesses through adapters with tested capabilities | A new model runner adds a large maintenance surface before product value is established |
| Usage | Deduplicated receipts plus rebuildable rollups and admission reservations | Counters inferred after launch cannot prevent simultaneous admissions or explain corrections |
| Rollout | Observe, prove control contracts, then managed pilot | Shipping hidden workers before reliable reporting can reduce visible noise by concealing obligations |

The earlier design panel's “one new table” constraint is withdrawn. Durable delivery, admission and usage have distinct lifecycles. They need clear ownership and replay rules even when some records can reuse existing tables. Choose the smallest schema that preserves those invariants, not a numerical table target.

### Questions resolved by engineering

The organizational parent points at a role, so replacing a session does not rewrite reporting history. The UI resolves the live session when it needs to show a conversation. A departed session keeps its history and loses authority to affect the current role generation.

Vacancy and escalation differ. A task can remain assigned to a vacant lead while its pending decision routes to the next eligible actor. This keeps responsibility visible and prevents a temporary outage from silently reorganizing the project.

The human control path remains available when agent execution is paused or out of budget. Saving an answer or issuing stop cannot depend on admitting another model turn. Execution resumes only when an eligible permit and valid approval exist.

Summary generation preserves the audience of its inputs. A broad project lead cannot copy private task details into a public channel because it can read them. The receiving surface must be entitled to the disclosed facts. Deleting or revoking access removes cached previews as well as server reads.

Retention preserves work. An idle process may hibernate; a completed attempt may archive. Neither action authorizes deletion of dirty files, unmerged commits or artifacts still under review. The cleanup preview must identify those conditions.

### Test and release map

Use contract fixtures shared across server, CLI, web and mobile for scope selection, next actor, generation, admission and projection. Add integration tests at the mutation/daemon boundary; do not rely solely on mocked happy paths. The failure matrix in section 8 supplies expected outcomes.

The proposed work should run the repository's relevant unit, type, lint and integration gates in each implementation phase. UI acceptance includes actual browser behavior, keyboard focus, mobile layouts and replica recovery. Validate mixed client versions before enabling managed mode for existing users.

Deployment follows the repository's release ordering: additive backend support first through `packages/convex/deploy.sh`, then compatible clients, then feature activation. The deploy script's freshness guard matters because Convex deploys a whole source snapshot. CLI/daemon capabilities are independently versioned; the web must not enable a managed operation simply because its button exists.

Rollback stops new managed admissions and restores human routing with visible pending work. It preserves tasks, decisions, provenance, receipts and historical reports. Do not roll back by dropping columns or erasing evidence. A repair can replay durable operations once the corrected version is available.

### Terminology

| Term | Meaning |
|---|---|
| Role / lead | Durable responsibility at a workspace, project or plan, represented by an anchor |
| Session | One conversation and its execution history; it may be active, parked, replaced or complete |
| Worker | A temporary session executing a specific authorized attempt |
| Human owner | Person accountable for the work, distinct from the host or coordinator |
| Scope | Work boundary and references to existing entities; access still requires the relevant checks |
| Generation | Monotonic fence for a role holder or a task attempt; the two counters are independent |
| Attempt | One claimed execution of a task, including its lease, evidence and disposition |
| Permit | Durable admission decision with reserved resources and an idempotent execution operation |
| Receipt | Evidence of execution or consumption from an identified source |
| Digest | A bounded view of current recorded facts, linked evidence, uncertainty and next actions |
| Observer | A lead allowed to inspect and recommend within its access, without autonomous execution control |
| Managed mode | Explicitly adopted work using supported identity, permission, admission and recovery contracts |

### Research and review record

This proposal reuses three codebase inventories, four independent designs, three design judgments and a synthesis from the earlier workflow. Ten section drafts and their rendered fragments survived the failed assembly jobs. The continuation repaired missing content and used independent Codex architecture and product reviewers to challenge the design.

The final editing pass resolved the major disagreements: authenticated authority versus claimed identity, real admission versus delayed accounting, stable provenance through rotation, explicit adoption, durable event acknowledgment, private evidence and measurable product value. The proposal itself is the deliverable. No agent organization feature has been implemented or deployed as part of this work.

The detailed validation record accompanies the page source. It records the ten final polish passes, browser checks and outstanding product choices. Future implementation estimates and success targets remain hypotheses until the pilot measures them.
