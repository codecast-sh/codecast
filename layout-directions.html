Tasks, docs & sessions:
layout should follow intent

Today the workspace can end up as five live columns — nav, list, doc, the session you're watching, the inbox rail — each with its own resize handle, collapse chevron and close button. Getting to a good reading view takes three or four adjustments; getting back to triage takes three or four more. The fix isn't a better splitter. It's making the arrangement a small set of discrete states that one gesture switches between — so side by side is there when you want it and gone when you don't.

Where the friction is

The real structure
  • Three layers, blind to each other — the list / detail split inside the page, the global session column, and the inbox rail each keep their own width and collapse state.
  • No layer can see the whole layout, so no single gesture can fix it.
  • Reading a doc well means: collapse the list, close the session column, fold the rail. Triage means undoing all three.
The tension to honor
  • Side by side is genuinely valuable: triaging while a session runs, reading a doc against a conversation.
  • And side by side is genuinely costly: reading and writing want one wide, quiet surface.
  • Both are right. The layout has to move between them cheaply — right now the user is the motor.

Direction 1

Peek, then pin

Side by side is a moment, not a place. Lists get the full width and stay calm. Selecting an item opens it over the list, not beside it. If this is the moment you want both, you pin — and the overlay becomes a real split. esc always retreats one step.

Borrowed from
  • Linear's peek (space / ⌘↵ to promote)
  • Notion's side peek on database rows
  • Every good mail client
What it fixes
  • No standing arrangement to manage — the split exists only because you asked, and closes back to a clean list.
  • Reading defaults to a wide surface; browsing defaults to a wide list. Nothing to resize.
What it costs
  • While peeking, the list under the overlay is partly hidden.
  • Watching a session while reading needs the explicit pin — one more gesture than today.

Direction 2

One stage, one rail

A hard cap: two regions, ever. The stage holds the thing you're working on. One rail holds everything secondary — the inbox, the list you came from, a session you're watching — as tabs in a single slot. Opening something from the rail promotes it to the stage; what was on stage stays one tab away. Things swap; they never accumulate.

Borrowed from
  • Slack — threads, details, canvases all share one right rail
  • VS Code's single side panel
What it fixes
  • Columns cannot pile up — the five column screenshot becomes unrepresentable, by design.
  • One splitter total, snapping to fixed ratios. "Watch a session while reading" is first class, not an arrangement you build.
What it costs
  • The cap is real: two sessions and a doc at once is impossible.
  • Rail tabs hide state — the inbox needs a badge to stay trustworthy.

Direction 3

Layout modes

Keep today's regions; quantize the arrangement. Three named states — Focus, Split, Triage — and one key that cycles them. Every surface remembers its own last mode: Docs can live in Focus while Sessions lives in Triage, and switching surfaces restores each. Splitters snap to ratios; there is no freeform pixel dragging to get wrong.

Borrowed from
  • tmux layout cycling (prefix space)
  • OS window snapping — quantized, never freeform
What it fixes
  • Intent switch = one keystroke, not four adjustments. And it's reversible the same way.
  • You can never end up in a broken in-between layout — every state is designed.
  • Smallest code delta: it's a thin policy layer over the panels that already exist.
What it costs
  • Triage is still dense — this tames switching, not density.
  • Mode proliferation is the failure mode. Three is the number; "just one more" is the trap.
l cycle modeclick Docs / Sessions in nav — each remembers its mode
Direction 4

Folding columns

Everything stays; attention pays. Keep the multicolumn model, but a column you're not using folds itself to a thin labeled edge — the current « control made automatic and universal. At most two columns are open at once: focusing one opens it, and the least recently used one folds to make room. Nothing is ever closed, only thin — so the spatial map never breaks.

Borrowed from
  • Miller columns (the Finder's column view)
  • Accordions; the existing collapsed rail, promoted from manual to automatic
What it fixes
  • Zero width management — you never resize, you just look somewhere and it opens.
  • Side by side is always one click away, and so is a wide reading pane.
  • Everything keeps its place; muscle memory survives.
What it costs
  • The UI moves on its own — a fold you didn't ask for can feel like the floor shifting.
  • The folded edges are still chrome; "two open max" is policy that will need tuning per screen width.
click a folded edge → it opens, the stalest open column folds

They compose

These aren't four rival futures — they're layers, and the strongest path stacks three of them.

Modes as the backbone (3). One global arrangement state with per surface memory replaces every independent collapse and resize. It's also the cheapest to ship, because it sits on the panel system that already exists.

Peek inside list surfaces (1). Tasks, docs and session lists stop reserving a permanent detail split; selection peeks, p pins into Split mode when the moment calls for it. Pinning is switching modes — the two ideas are one mechanism.

The rail discipline for the right side (2). The session column and the inbox rail are today two separate right hand regions that can both be open. Make them one rail with tabs — the inbox, the watched session, comments — and the five column pileup becomes structurally impossible while losing nothing people actually do.

Direction 4 is the wildcard: lovely to use, hardest to make feel calm. Worth a prototype behind a flag once the backbone exists.
