## Ordering and shared ownership

- Begin with 001, 002's patch/session authorization, and 003's chart sink. They do not depend on each other and should not wait for broad refactors.
- Finish content/desktop and local/integration/publishing boundaries next. Small admission fixes need not wait for an iframe/capability redesign.
- 001 and 007 share canonical platform auth and must serialize mirror refreshes. 004 and 008 share CLI bridge dependency tests. 003 and 006 must agree on content/origin policy while retaining distinct canvas and arbitrary published-page contracts.
- 008's endpoint matrix begins early and becomes the final cross-workstream acceptance gate. Assign one release owner before deployment to track backend, web, CLI, extension, desktop and mobile compatibility.
- Preserve explicit runner handovers, local-first state, personal workspace access and interactive publishing. A broad permission restriction that breaks those requirements is not a complete fix.

## Considered and rejected claims

- Extension HMAC bypass, browser-controlled RFC6455 fragmentation, and packaged-default CDP exposure were not established.
- Inline img SVG execution, arbitrary iframe IPC, arbitrary-file transcript upload and automatic all-symlink exfiltration overstate the evidence.
- Authorized repository setup commands, selected remote hosts and opt-in credential forwarding are capabilities to scope, not vulnerabilities by themselves.
- Storage-ID capability semantics and unverified GitHub profile metadata require downstream policy/usage review before severity assignment.
- Raw audit counts are not exploit counts; runtime import and affected call-path proof are required.
